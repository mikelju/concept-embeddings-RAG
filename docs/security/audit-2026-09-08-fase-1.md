# Security Audit — concept-embeddings-RAG

**Date:** 2026-09-08
**Auditor:** audit-code skill (Claude Code)
**Scope:** Phase 1 — all of `src/concept_embeddings_rag/` (20 files), `pyproject.toml`, `.gitignore`, `.github/workflows/security.yml`, plus spot-checks of `tests/`
**Threat model:** local single-user research pipeline (CLI). No network service, no authentication, no multi-tenancy, no PII. The assets worth protecting are (a) the developer's machine, against code executed by artifacts the pipeline loads, and (b) **the integrity of the measurements**, which are this project's entire deliverable
**Stack:** Python 3.12.10 (win_arm64), numpy 2.5.2, scikit-learn 1.9.0, sentence-transformers 6.0.1, torch 2.13.0+cpu, transformers 5.16.1, httpx 0.28.1, bm25s 0.3.11
**Commit:** `5b773b4`

---

## 1. Executive Summary

This is a local research pipeline with a genuinely small attack surface: no web server, no database, no user accounts, no shell execution, and no `pickle` anywhere. The deliberate security choices documented in the phase plan hold up under reading — the embedding cache loads with `allow_pickle=False` and validates its contents before use, the manifest refuses unknown fields, and no credentials appear anywhere in the code or in git history.

The findings concentrate in one theme, and it is the theme that matters most for a research project: **integrity controls that exist in the code but are never actually exercised by the pipeline**. The corpus hash is recorded but never compared against anything; the function that would compare it is called only from tests. The embedding model is fetched from a branch name rather than a pinned commit, so the artifact that produces every number in the project is neither reproducible nor verified. The unit pool is reloaded from disk without checking that its content-derived identifiers still match their content.

None of these is remotely exploitable, and none puts the machine at risk. All three do mean that a corrupted or substituted artifact would be consumed silently and would falsify results without leaving a trace — which, for a project whose deliverable is measured evidence, is the failure mode that costs the most. No critical or high findings under the reviewed scope.

## 2. Top Priorities

1. **[SEC-001] The corpus hash is recorded but never verified** — `cer fetch` recomputes the digest of whatever is on disk and writes it into the manifest as if it were confirmation, so a tampered or truncated corpus is silently blessed. The function that does the real check is dead code outside the test suite. -> §3.1
2. **[SEC-002] The embedding model is pinned to `main`, not to a commit** — every vector in the project comes from whatever `BAAI/bge-small-en-v1.5` happened to be at download time, and the cache sidecar records the string `"main"` rather than the resolved revision, contradicting the comment in `config.py`. -> §3.2
3. **[SEC-003] `load_pool` trusts unit ids it does not verify** — ids are content-derived, so re-deriving them costs nothing, but nothing does. A hand-edited `pool.json` could point a gold id at a different paragraph and every metric downstream would move. -> §3.3

## 3. Findings

### 3.1 [SEC-001] Corpus integrity check is recorded, never enforced — **Medium**

- **File:** [cli.py:49-68](../../src/concept_embeddings_rag/cli.py#L49-L68), [download.py:39-73](../../src/concept_embeddings_rag/corpus/download.py#L39-L73)
- **CWE:** CWE-354 (Improper Validation of Integrity Check Value)
- **OWASP:** A08 — Software and Data Integrity Failures
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`download.ensure_corpus()` implements the correct pattern: it compares the file's SHA-256 against an expected value and raises `CorpusIntegrityError` on mismatch. The CLI never calls it. `cmd_fetch` imports only `sha256_of_file`, sees that the file exists, hashes whatever is there, and writes that digest into a freshly constructed manifest. The hash is therefore always self-consistent by construction and can never fail.

`cmd_build` compounds this: it loads the manifest and then reads `hotpot_raw.json` directly, copying `manifest.sha256` forward (line 99) without ever comparing it to the file it is about to parse. The docstring in `manifest.py` states that "nothing downstream reads the raw benchmark file directly" — in practice `cmd_build` does exactly that.

`grep` confirms the scope: `ensure_corpus` appears in `download.py` and in `tests/corpus/test_download.py`, and nowhere else.

**Vulnerable code**

```python
# src/concept_embeddings_rag/cli.py:49-68
    if raw_path.exists():
        print(f"[INFO] corpus already present at {raw_path}")
    else:
        rows = hf_source.fetch_split(pause=0.5)
        raw_path.write_text(json.dumps(rows, sort_keys=True), encoding="utf-8")
    digest = sha256_of_file(raw_path)          # describes, never compares

    manifest = CorpusManifest(
        ...,
        sha256=digest,                          # a manifest that always agrees with itself
    )
```

**Impact**

No code execution: the payload is JSON parsed by `json.loads`. The impact is on measurement integrity. Any corruption of `data/hotpot_raw.json` — a truncated write, a partially downloaded file recovered from a crash, a hand-edit, a sync conflict — is absorbed without a warning, and the manifest is rewritten to certify the damaged file. Since the manifest is the artifact that gives every number in the project its provenance, and it is committed to git, the result is a provenance record that asserts an integrity check which never ran.

This also fails the HU-1 acceptance criterion as written: *"a second run verifies the hash instead of downloading again."* The second run recomputes; it does not verify.

**Reproduction / PoC sketch** (do NOT run)

> Append a single byte to `data/hotpot_raw.json` and re-run `cer fetch`. Expected behaviour: an error naming the hash mismatch. Actual behaviour: `[INFO] corpus already present`, followed by `[OK] corpus frozen` quoting the new digest, and a rewritten `manifest.json`. The git diff on the manifest is the only surviving evidence, and only because the manifest happens to be versioned.

**Remediation**

Make the pipeline call the verification that already exists, and verify before parsing:

```python
# src/concept_embeddings_rag/cli.py:43 — fixed
def cmd_fetch(data_dir: Path = config.DATA_DIR, seed: int = config.DEFAULT_SEED) -> Path:
    data_dir = Path(data_dir)
    data_dir.mkdir(parents=True, exist_ok=True)
    raw_path = data_dir / RAW_NAME
    manifest_path = data_dir / MANIFEST_NAME

    # A manifest from an earlier run is what makes this a verification and not a
    # description: without an expected hash there is nothing to check against.
    expected = CorpusManifest.load(manifest_path).sha256 if manifest_path.exists() else None

    if raw_path.exists():
        actual = sha256_of_file(raw_path)
        if expected is not None and actual != expected:
            raise CorpusIntegrityError(
                f"{raw_path} has hash {actual}, manifest expects {expected}; "
                "delete the file to re-fetch it deliberately"
            )
        print(f"[INFO] corpus already present and verified at {raw_path}")
    else:
        ...
```

```python
# src/concept_embeddings_rag/cli.py:85 — fixed (cmd_build)
    manifest = CorpusManifest.load(manifest_path)
    actual = sha256_of_file(raw_path)
    if actual != manifest.sha256:
        _die(f"corpus at {raw_path} does not match the manifest hash; re-run 'fetch'")
    raw_questions = json.loads(raw_path.read_text(encoding="utf-8"))
```

Note the deliberate choice to fail rather than re-download: `ensure_corpus`'s `redownload_on_mismatch=True` default silently replaces a file that failed verification, which destroys the evidence of what went wrong. For a frozen research corpus, failing closed and asking the human is the right default.

Add the regression test the current suite lacks: build a manifest, mutate the raw file, assert that both `cmd_fetch` and `cmd_build` raise.

**References**
- [CWE-354](https://cwe.mitre.org/data/definitions/354.html)
- [OWASP A08:2021 — Software and Data Integrity Failures](https://owasp.org/Top10/A08_2021-Software_and_Data_Integrity_Failures/)

### 3.2 [SEC-002] Embedding model and tokenizer resolved from a branch, not a pinned revision — **Medium**

- **File:** [config.py:38-40](../../src/concept_embeddings_rag/config.py#L38-L40), [backend.py:62](../../src/concept_embeddings_rag/embeddings/backend.py#L62), [budget.py:58](../../src/concept_embeddings_rag/evaluation/budget.py#L58)
- **CWE:** CWE-494 (Download of Code Without Integrity Check), with CWE-1357 (Reliance on Insufficiently Trustworthy Component)
- **OWASP:** A08 — Software and Data Integrity Failures
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`EMBEDDING_REVISION` is the literal string `"main"`. `SentenceTransformer(self.name, revision="main")` therefore resolves to whatever the tip of that repository's default branch is at download time, and `AutoTokenizer.from_pretrained(self.tokenizer_id)` in `budget.py` passes no `revision` at all. Fetching a model from the Hub downloads weights and configuration and loads them into the process; `transformers` 5.x defaults to `trust_remote_code=False`, modern torch defaults to `weights_only=True`, and `bge-small-en-v1.5` ships safetensors, so the realistic code-execution path is narrow — but the project has no control over which files it receives, and no record of which it received.

The comment in `config.py` claims the gap is covered:

> "the exact commit hash is recorded in the cache sidecar the first time the model is downloaded, which is what makes a run reproducible"

The sidecar on disk disproves it. `data/cache/embeddings-a28365b7ed90ed10.json` contains `"revision": "main"`, because `embed_units` copies `backend.revision` verbatim rather than asking the loaded model which commit it resolved to.

**Vulnerable code**

```python
# src/concept_embeddings_rag/config.py:38-40
# Pinned loosely for now; the exact commit hash is recorded in the cache sidecar
# the first time the model is downloaded, which is what makes a run reproducible.
EMBEDDING_REVISION: Final[str] = "main"
```

```python
# src/concept_embeddings_rag/evaluation/budget.py:58
            self._tokenizer = AutoTokenizer.from_pretrained(self.tokenizer_id)  # no revision
```

**Impact**

Two distinct consequences, the second more serious than the first.

*Supply chain*: if the upstream repository is compromised or force-pushed, the next machine to build this cache silently loads different artifacts. The blast radius is bounded by `trust_remote_code=False` and safetensors, so this is not a straight path to RCE — but it is an unverified download of executable-adjacent content into the process, with no pin and no hash.

*Reproducibility*: this is the one that bites. The project's stated success criterion is a "defensible and reproducible" answer, and `RunResult.config` records `"revision": "main"` as if it were provenance. A rerun in six months against an updated model would produce different vectors, different rankings and different numbers, while every artifact on disk continued to claim the same configuration. Phase 5's comparisons would rest on a baseline that can no longer be regenerated.

**Reproduction / PoC sketch** (do NOT run)

> No attack is needed to demonstrate the reproducibility half: resolving `BAAI/bge-small-en-v1.5@main` today and after any upstream commit returns different snapshot directories, while `manifest.json`, the cache sidecar and all four `RunResult` files continue to read `"revision": "main"`. Nothing in the recorded provenance distinguishes the two runs.

**Remediation**

Pin the commit, and record what was actually resolved:

```python
# src/concept_embeddings_rag/config.py — fixed
# Pinned to a commit, not a branch: a moving revision silently redefines every
# vector in the project and every number derived from them.
EMBEDDING_REVISION: Final[str] = "<commit sha of the snapshot currently cached>"
```

```python
# src/concept_embeddings_rag/embeddings/backend.py — fixed
    def resolved_revision(self) -> str:
        """The commit actually loaded, recorded so a rerun can be compared to this one."""
        from huggingface_hub import snapshot_download

        path = snapshot_download(self.name, revision=self.revision)
        return Path(path).name  # snapshots/<commit sha>
```

Store that value in the cache sidecar and in `RunResult.config` under a distinct key (`resolved_revision`), and pass `revision=config.EMBEDDING_REVISION` to `AutoTokenizer.from_pretrained` too.

Until the pin lands, correct the comment in `config.py`. A comment asserting a control that does not exist is worse than no comment, because it stops the next reader from looking.

Caveat: pinning invalidates nothing by itself, but changing the *model* would invalidate the 36-minute embedding cache. Pin to the commit already on disk so the cache stays valid; confirm the sha against the Hub before committing the constant.

**References**
- [CWE-494](https://cwe.mitre.org/data/definitions/494.html)
- [Hugging Face — model versioning and `revision`](https://huggingface.co/docs/hub/models-downloading)

### 3.3 [SEC-003] `load_pool` does not re-derive the content-addressed ids it loads — **Medium**

- **File:** [pool.py:148-168](../../src/concept_embeddings_rag/corpus/pool.py#L148-L168)
- **CWE:** CWE-345 (Insufficient Verification of Data Authenticity)
- **OWASP:** A08 — Software and Data Integrity Failures
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`unit_id_for(title, sentences)` makes the id a pure function of content — the design decision that makes deduplication free and rebuilds identical. `load_pool` then reads `pool.json` and takes each stored `unit_id` at face value, never re-deriving it from the `title` and `sentences` sitting beside it in the same object. The check costs one hash per unit (19,366 SHA-1s, well under a second) and is not performed.

Nor is the pool checked against the manifest: `manifest.unit_set_hash` exists precisely to identify a pool, and both `cmd_embed` and `cmd_evaluate` call `load_pool` without ever comparing it.

The embedding cache, by contrast, gets this right — `EmbeddingCache.load` refuses to return vectors whose id list does not match the expected units ([cache.py:92-95](../../src/concept_embeddings_rag/embeddings/cache.py#L92-L95)). The pool deserves the same treatment and does not have it.

**Vulnerable code**

```python
# src/concept_embeddings_rag/corpus/pool.py:153-156
    units = [
        IndexingUnit(unit_id=u["unit_id"], title=u["title"], sentences=tuple(u["sentences"]))
        for u in payload["units"]
    ]
```

**Impact**

Data integrity only; no execution. An edited or corrupted `pool.json` — a gold id swapped, a paragraph's text changed while its id stays — is loaded without complaint. Because gold ids are what every metric is scored against, a single altered id shifts Gold Recall, Full Support and Precision for every affected question, and nothing downstream would contradict it. The retrievers would happily index the substituted text and the numbers would look entirely ordinary.

This matters more here than it would elsewhere because `pool.json` is a regenerable intermediate that is *not* versioned (`.gitignore` line 35 excludes it), so there is no git history to catch a divergence.

**Reproduction / PoC sketch** (do NOT run)

> Edit one `sentences` entry in `data/pool.json`, leaving its `unit_id` untouched, then re-run `cer evaluate`. The pool loads, BM25 reindexes the altered text, the cached embeddings still match by id, and the run writes a `RunResult` whose `unit_set_hash` is unchanged — because that hash is computed from the ids, which were never checked against their content.

**Remediation**

```python
# src/concept_embeddings_rag/corpus/pool.py:148 — fixed
def load_pool(path: Path | str) -> tuple[list[IndexingUnit], list[Question]]:
    """Load the pool, re-deriving every id so a tampered file cannot pass as intact."""
    payload = json.loads(Path(path).read_text(encoding="utf-8"))

    units = []
    for entry in payload["units"]:
        sentences = tuple(entry["sentences"])
        expected = unit_id_for(entry["title"], sentences)
        if expected != entry["unit_id"]:
            raise GoldResolutionError(
                f"unit {entry['unit_id']} does not hash to its content (got {expected}); "
                f"{path} has been modified - rebuild it with 'build'"
            )
        units.append(
            IndexingUnit(unit_id=entry["unit_id"], title=entry["title"], sentences=sentences)
        )
    ...
```

Defence in depth: have `cmd_embed` and `cmd_evaluate` compare `unit_set_hash([u.unit_id for u in units])` against `manifest.unit_set_hash` and refuse to proceed on mismatch. The value is already computed and stored; it is simply never read back.

**References**
- [CWE-345](https://cwe.mitre.org/data/definitions/345.html)

### 3.4 [SEC-004] Unbounded pagination and unbounded response size when assembling the corpus — **Medium**

- **File:** [hf_source.py:102-122](../../src/concept_embeddings_rag/corpus/hf_source.py#L102-L122), [download.py:30-36](../../src/concept_embeddings_rag/corpus/download.py#L30-L36)
- **CWE:** CWE-770 (Allocation of Resources Without Limits or Throttling)
- **OWASP:** A04 — Insecure Design
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`fetch_split` loops `while True`, accumulating every row in memory, and its only exits are an empty page or `offset >= total`. The second guard is written `if total and offset >= total`, so when the API omits `num_rows_total` or returns `0`, `total` is falsy and that exit is disabled — leaving an empty page as the sole termination condition. A peer that keeps returning non-empty pages keeps the loop running and the list growing.

Separately, both HTTP paths read entire responses into memory with no size ceiling: `response.content` in `download._http_fetcher` and `response.json()` in `_http_page_fetcher`. Timeouts are set on both (300 s and 120 s), which is more than most code gets, but a timeout bounds duration, not bytes.

**Vulnerable code**

```python
# src/concept_embeddings_rag/corpus/hf_source.py:104-118
        if total is None:
            total = int(payload.get("num_rows_total", 0))   # absent -> 0 -> guard disabled
        ...
        if total and offset >= total:                        # falsy total never terminates here
            break
```

**Impact**

Local denial of service: memory exhaustion or a hung `cer fetch`. There is no attacker in the normal threat model — the peer is the HuggingFace datasets server over TLS — so realistically this triggers on an API change, a malformed response, or a proxy returning unexpected JSON, not on an attack. On a laptop that also runs a 36-minute embedding job, an OOM is a real cost even when nobody is hostile.

**Reproduction / PoC sketch** (do NOT run)

> A response shaped `{"rows": [...100 rows...]}` with `num_rows_total` absent sets `total = 0`. Every subsequent page is requested and appended; the loop ends only if a page comes back empty. A proxy replaying the same page indefinitely turns `cer fetch` into an unbounded allocation.

**Remediation**

```python
# src/concept_embeddings_rag/corpus/hf_source.py:89 — fixed
MAX_ROWS = 20_000   # the distractor validation split holds 7,405; well clear, but finite

def fetch_split(..., max_rows: int = MAX_ROWS) -> list[dict]:
    ...
    while True:
        ...
        rows.extend(normalize_row(entry["row"]) for entry in page)
        offset += len(page)
        if len(rows) > max_rows:
            raise RuntimeError(
                f"fetched {len(rows)} rows, past the {max_rows} ceiling; "
                "the API shape has probably changed"
            )
        if total and offset >= total:
            break
```

For the download path, stream and cap:

```python
# src/concept_embeddings_rag/corpus/download.py:30 — fixed
MAX_CORPUS_BYTES = 512 * 1024 * 1024


def _http_fetcher(url: str) -> bytes:
    import httpx

    with httpx.Client(follow_redirects=True, timeout=300.0) as client:
        with client.stream("GET", url) as response:
            response.raise_for_status()
            chunks, size = [], 0
            for chunk in response.iter_bytes():
                size += len(chunk)
                if size > MAX_CORPUS_BYTES:
                    raise CorpusIntegrityError(f"corpus exceeds {MAX_CORPUS_BYTES} bytes")
                chunks.append(chunk)
            return b"".join(chunks)
```

### 3.5 [SEC-005] SHA-1 used for content addressing without `usedforsecurity=False` — **Low**

- **File:** [pool.py:51](../../src/concept_embeddings_rag/corpus/pool.py#L51), [split.py:13](../../src/concept_embeddings_rag/corpus/split.py#L13), [cache.py:31](../../src/concept_embeddings_rag/embeddings/cache.py#L31), [cache.py:36](../../src/concept_embeddings_rag/embeddings/cache.py#L36)
- **CWE:** CWE-327 (Use of a Broken or Risky Cryptographic Algorithm)
- **OWASP:** A02 — Cryptographic Failures
- **Confidence:** Confirmed
- **Tool:** ruff `--select=S` (S324), confirmed by reading

**Description**

Four call sites use `hashlib.sha1` for non-cryptographic purposes: content-derived unit ids, the deterministic sort key for subset selection, the corpus identity hash and the cache key. These are content addressing and bucketing, not integrity or authentication, which the security checklist explicitly permits. The gap is that none of them declares that intent, so every SAST run flags them — and the CI `bandit` job (`-ll`, medium and above) will report B324 four times and fail the build.

Truncating to 16 hex characters (64 bits) keeps accidental collisions negligible at 19,366 units, and makes deliberate ones cheap for anyone who wants two paragraphs to share an id. In this threat model nobody does; in Phase 5, if a pool is ever assembled from a source outside the author's control, that stops being free.

**Vulnerable code**

```python
# src/concept_embeddings_rag/corpus/pool.py:48-51
def unit_id_for(title: str, sentences: tuple[str, ...]) -> str:
    """Content-derived identifier: same paragraph, same id, always."""
    payload = title + "\n" + " ".join(sentences)
    return hashlib.sha1(payload.encode("utf-8")).hexdigest()[:16]
```

**Impact**

No direct security impact under the current threat model. The practical cost is a CI gate that fails on findings nobody intends to fix, which trains the reader to ignore it.

**Remediation**

Declare the intent at every call site. `usedforsecurity=False` is understood by both `hashlib` (3.9+) and the scanners:

```python
# src/concept_embeddings_rag/corpus/pool.py:51 — fixed
    # Content addressing, not integrity: collisions are a correctness concern here,
    # not a security one, and the flag says so to hashlib and to the SAST gate alike.
    return hashlib.sha1(payload.encode("utf-8"), usedforsecurity=False).hexdigest()[:16]
```

Changing the algorithm is NOT recommended. `unit_id_for` and `unit_set_hash` feed the cache key, so switching to SHA-256 would invalidate the 36-minute embedding cache and make the recorded Phase 1 numbers incomparable with future ones. The flag achieves the same audit outcome at zero cost. If a wider id is ever wanted, do it as a deliberate documented cache rebuild between phases, not as a security fix.

**References**
- [CWE-327](https://cwe.mitre.org/data/definitions/327.html)
- [Python `hashlib` — `usedforsecurity`](https://docs.python.org/3/library/hashlib.html)

### 3.6 [SEC-006] Result filename is built from unvalidated `split` and `system` values — **Low**

- **File:** [harness.py:59-65](../../src/concept_embeddings_rag/evaluation/harness.py#L59-L65)
- **CWE:** CWE-22 (Improper Limitation of a Pathname to a Restricted Directory)
- **OWASP:** A01 — Broken Access Control
- **Confidence:** Possible
- **Tool:** manual review

**Description**

`RunResult.save` interpolates `self.system` and `self.split` straight into a filename. Both are trusted today: `system` is a class attribute on the retriever, and `split` is passed explicitly as `"dev"` or `"test"` by `cmd_evaluate`. But `evaluate_retriever` also derives it from `questions[0].split` when the argument is omitted, and that value travels from `pool.json` through `load_pool` with no validation — the same file SEC-003 shows is loaded unverified.

**Vulnerable code**

```python
# src/concept_embeddings_rag/evaluation/harness.py:59-61
        stamp = self.created_at.replace(":", "").replace("-", "")
        base = f"run-{self.system}-{self.split}-{stamp}"
        path = directory / f"{base}.json"
```

**Impact**

A `pool.json` whose questions carry `"split": "../../escaped"` would write the result JSON outside `data/results/`. Writing attacker-chosen JSON to an attacker-chosen path is normally serious; here it requires already being able to write `pool.json`, which means already having write access to the project directory, so it grants nothing new. Reported because the guard is one line and the input is one that SEC-003 shows is not otherwise checked.

**Reproduction / PoC sketch** (do NOT run)

> Set `"split": "../../../evil"` on every question in `pool.json` and call `evaluate_retriever` without the `split=` argument. `base` becomes `run-dense-../../../evil-...`, and `directory / base` resolves outside `data/results/`.

**Remediation**

```python
# src/concept_embeddings_rag/evaluation/harness.py:46 — fixed
    _SAFE_NAME = re.compile(r"^[A-Za-z0-9_-]+$")

    def validate(self) -> None:
        missing = REQUIRED_CONFIG_KEYS - self.config.keys()
        if missing:
            raise ProvenanceError(...)
        for label, value in (("system", self.system), ("split", self.split)):
            if not self._SAFE_NAME.match(value):
                raise ProvenanceError(f"{label} {value!r} is not usable in a filename")
```

Validating inside `validate()` means `save()` already calls it, so the check lands on exactly the path that writes the file.

### 3.7 [SEC-007] CI secret scanning cannot fail, and the dependency gate runs on the wrong Python — **Low**

- **File:** [security.yml:64-71](../../.github/workflows/security.yml#L64-L71), [security.yml:100-106](../../.github/workflows/security.yml#L100-L106)
- **CWE:** CWE-1188 (Insecure Default Initialization of Resource)
- **OWASP:** A05 — Security Misconfiguration
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

Two of the three Python security gates do not do what the workflow's header comment promises.

*Secrets*: with no `.secrets.baseline` in the repo — there is none — the job runs `detect-secrets scan --all-files`. `scan` writes its findings to stdout and exits 0 regardless of what it finds. The job is green whether or not a credential is committed.

*Dependencies*: the job installs Python 3.11, but `pyproject.toml` requires `>=3.12,<3.13`. The `pip install -e .` branch fails on the `Requires-Python` constraint, so `pip-audit` never runs on this project's dependency tree. The same 3.11 pin applies to the `bandit` job, which will additionally report B324 four times once it does run (see SEC-005).

**Vulnerable code**

```yaml
# .github/workflows/security.yml:67-71
        run: |
          if [ -f .secrets.baseline ]; then
            detect-secrets audit .secrets.baseline
          else
            detect-secrets scan --all-files      # exits 0 no matter what it finds
          fi
```

**Impact**

A false sense of coverage. `CLAUDE.md` gotcha 7 defers local security tooling on the grounds that "the workflow already runs them in CI" — but as written the secrets gate cannot fail and the dependency gate cannot run. ### 3.8 [SEC-008] `CorpusManifest.from_dict` validates field names but not their types — **Low**

- **File:** [manifest.py:47-62](../../src/concept_embeddings_rag/corpus/manifest.py#L47-L62)
- **CWE:** CWE-20 (Improper Input Validation)
- **OWASP:** A08 — Software and Data Integrity Failures
- **Confidence:** Confirmed
- **Tool:** manual review

**Description**

`from_dict` does the important half well: it rejects missing required fields and, notably, rejects unknown ones before `cls(**payload)`, which closes the mass-assignment shape this pattern usually opens. What it does not do is check types. `seed` could be a string, `split_sizes` could map to strings, `sha256` could be any text at all. A `frozen=True` dataclass performs no runtime type enforcement, and `__post_init__` only sums the split sizes.

**Impact**

Low and mostly self-correcting: a wrong-typed `split_sizes` raises `TypeError` inside `__post_init__`, and a wrong-typed `seed` surfaces later in `_sort_key`. Both fail closed. The residual risk is a `sha256` field holding a non-hash string, which starts to matter once SEC-001 is fixed and that field is actually compared.

        if not isinstance(self.seed, int):

### 3.10 [OBS-002] Trust-on-first-use is this pipeline's real security boundary — **Info**

- **File:** [manifest.py:1-6](../../src/concept_embeddings_rag/corpus/manifest.py#L1-L6)
- **Confidence:** Confirmed

Even with SEC-001 fixed, `manifest.json` and `hotpot_raw.json` sit in the same directory with the same permissions, so anyone who can alter the corpus can alter the hash that vouches for it. This is inherent to trust-on-first-use and is not worth engineering away here — an attacker with write access to the project directory has already won more than this.

## 4. Defense-in-Depth Recommendations

- **[DEF-001] Add a `verify` subcommand.** A fifth CLI stage that re-checks the corpus hash, re-derives every unit id and compares the pool against `manifest.unit_set_hash` would turn SEC-001 and SEC-003 into one reproducible command, and would give `/7-verificar` something executable to point at in later phases.
- **[DEF-002] Record resolved versions, not requested ones.** Beyond SEC-002: `RunResult.config` would be stronger carrying the resolved model commit, the `sentence-transformers`/`torch` versions and the git SHA of the code. `code_version` is `0.1.0` and will not change between commits, so it cannot distinguish two runs of different code.
- **[DEF-003] Add `S` to the ruff lint selection.** `select = ["E", "F", "I", "UP", "B", "SIM", "S"]` with `per-file-ignores = {"tests/**" = ["S101"]}` puts SAST in the local loop instead of only in CI — which is where the four SHA-1 findings would have surfaced before the commit. On a codebase this size it subsumes most of what the CI `bandit` job provides.
- **[DEF-004] Fail closed on artifact mismatch, never re-download.** `ensure_corpus(redownload_on_mismatch=True)` silently replaces a file that failed verification. For a frozen research corpus the default should be to stop and report; overwriting destroys the only evidence of what diverged.
- **[DEF-005] Keep Phase 2 free of `pickle`.** Phase 2 introduces `MiniBatchDictionaryLearning`, and the reflex for persisting a fitted scikit-learn object is `joblib.dump` — which is pickle, and therefore arbitrary code execution on load. The dictionary is a plain array: persist atoms and parameters as `.npz` plus a JSON sidecar, exactly as the embedding cache already does.
- **[DEF-006] Treat the Phase 2 `ANTHROPIC_API_KEY` as this project's first real secret.** No secret exists in the codebase today. When concept labelling arrives, the key must come from `.env` through the environment, never appear in an `[INFO]` line, and never be written into a cached artifact or a `RunResult`.
