# Phase 16 — RunPod operating recipe

> Operational runbook for the **pod half of plan step S3**: the BGE-small encoding (`embed`) and
> the GLiNER extraction (`extract`) over the MultiHop-RAG corpus. Everything else in S3 runs on
> the laptop: `bm25` before the pod (done), `index` after it.
>
> This is [`15.runpod_recipe.md`](../phase_15/15.runpod_recipe.md) with only the differences the
> plan lists (`16.0_multihop_rag_validation.md`, "The pod recipe"): paths, commands, sizes and
> SHA-256 of the uploads, expected checks, projected durations and cost, and a **1 USD** guard.
> Every step not repeated here in full (the env file on the volume, `uv sync --group phase7`,
> the CUDA kernel check, the machine recorded by hand, `nohup` one step at a time, `sha256sum`
> on both sides, terminate, copy Billing) is Phase 15's, word for word, with `phase15` read as
> `phase16` and `p15-build` as `p16-build`.
>
> **Stop point 1.** Nothing here is started before the author approves this recipe, the rate and
> the frozen commit. On the pod, **if the session reaches 1 USD, stop the pod and ask the author
> before anything else.**
>
> No metric of any MultiHop-RAG query is computed on the pod. The pod encodes and extracts; it
> retrieves nothing. Labels: **measured** (read off an artifact), **derived** (arithmetic on
> measured values), **projection** (not a measurement).

## 7. Build: one process per step, one step at a time

**Step 1, `embed`** (under 1 min, projection):

```bash
nohup uv run --group phase7 cer p16-build --stage embed --hourly-rate-usd <RATE> > data/phase16/logs/embed.log 2>&1 &
tail -n 3 data/phase16/logs/embed.log     # repeat until "[OK] p16-build embed"
```

**Step 2, `extract`**, only after step 1 printed `[OK]` (under 5 min, projection):

```bash
nohup uv run --group phase7 cer p16-build --stage extract --hourly-rate-usd <RATE> > data/phase16/logs/extract.log 2>&1 &
tail -n 3 data/phase16/logs/extract.log   # repeat until "[OK] p16-build extract"
```

- `embed` writes `data/phase16/cache/` and `data/phase16/cache/questions/` (the 2,255
  answerable and 301 live-path query vectors, in that order). It refuses to run twice.
- `extract` writes `data/phase16/nodes/`, **one shard** (100,000 units per shard). Resumable:
  if it dies, rerun the same line once; a second failure: STOP.
- Any refusal: STOP.

Quick look (no metric involved):

```bash
python3 -c "import json; b = json.load(open('data/phase16/cache/embedding.json')); print(b['n_units'], b['n_questions'], b['wall_seconds'], b['paragraphs_per_second'], b['hardware']['gpu'])"
python3 -c "import json; b = json.load(open('data/phase16/nodes/extraction.json')); print(b['configuration_digest'], b['configuration_digest_matches'], b['attempted'], b['failures'], b['wall_seconds'], b['hardware']['gpu'], b['gliner_window']['units_over'])"
```

The first must show **27989** and **2556**; the second **`2f7864661b8ce7ff True 27989`**, 0
failures, and **46** units over the window (the S2 count, carried).
