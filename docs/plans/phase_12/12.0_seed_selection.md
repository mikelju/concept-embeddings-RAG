# Phase 12: choosing with the question which of P1's entities to hop from — implementation plan

> Functional spec: [`12.spec.md`](12.spec.md), approved 2026-09-27 and frozen (one wording
> correction the same day, no rule changed). This plan was **approved by the author on
> 2026-09-27**. It decides HOW; a change to any spec rule is a written deviation `12.Y_*.md`.
>
> Simplification rule: one question, **seven steps**, no `12.tasks.md`, reuse before
> generalization. Everything runs on the laptop; no money is spent.

## Objective

> Does choosing, with the question, which of P1's entities the hop starts from (instead of
> starting from all of them) retrieve the full multi-hop evidence more often than P10-C at
> FullWiki scale?

Primary endpoint: Full Support @2,048 on `test-11` (5,000 HotpotQA train `hard` questions), P12
against frozen P10-C, one two-sided exact McNemar test, α = 0.05. Preregistered secondary: P12
against P10-B, same test; it cannot change the label. Terminal states: `SEED_SELECTION_SUPPORTED`,
`SEED_SELECTION_NOT_SUPPORTED`, `SEED_SELECTION_REGRESSION`, `DEV_STOP`.

## Author stop points

1. **Before the held-out pass (S6).** It opens `test-11`. It runs once, after `fit.json` is
   committed, and only on explicit authorization.
2. A D4 reproduction miss (S4), `DEV_STOP` (S5), or two attempts without progress.

      - uses the Phase 11 `test-11` question vectors (key `3ab80134c058052d`);

## Technical notes

- **Reuse.** The plan reuses:
  - inputs: `_phase_9_inputs`, `_phase_9_corpus`, `_p11_entity_index`, the Phase 10 dev lists
    and `phase11.load_test_11`;
  - hop and fusion: `second_hop.seeded_hop_columnwise`, `fuse_lists` and `ReplayRetriever`;
  - measurement: `supported`, `gold_recall_sum`, `measure_system`, `write_run`,
    `latency_summary` and `exact_two_sided_p`;
  - checks and shapes: `_p10_fit_is_committed`, the write-once helpers and
    `phase11.reproduction_verdict`'s shape.

  The Phase 9 hop and the Phase 10/11 stages are not modified.
- **Why the identity holds.** At `s = all, x = no`, the seed set is every entity node of P1.
  `seeded_hop_columnwise` with those seeds equals `node_hop_columnwise` bit for bit; Phase 11
  held this by test and on the real index. S3 re-tests it for the new stage, and D4 checks it on
  all 7,405 dev questions.
- **Where the sentences come from.** `IndexingUnit.sentences` of the Phase 9 corpus: the
  paragraph's own HotpotQA sentence split. The title is not a sentence, so an entity that appears
  only in the title is unlocated.
- **Question vectors.** Dev reads the Phase 9 vectors (encoded on the rented GPU in Phase 9) and
  `test-11` reads the Phase 11 vectors (laptop CPU). The sentence vectors are encoded on the
  laptop CPU for both sets. The CPU/GPU numeric difference is expected to reorder sentences
  only rarely; this is a hypothesis, not a measurement. It is recorded as a limitation, not
  corrected.
- **Latency.** `measure_system` times the whole `retrieve`. `OnlineSentences` times its own
  encoder calls per question. The report gives the difference as `retrieve` and the encoder time
  beside it, so the D8 figure stays comparable with Phase 10's. On `test-11` each P1's sentences
  are encoded in one batch the first time that unit is P1; later questions with the same P1
  reuse them, as a real system with a small cache would.
- **Time (projection, not measurement).**
  - S2: about 30,000 sentences. Phase 10 encoded 5,000 questions in 94 s and Phase 11 in 207 s,
    so about 10-25 min.
  - S4: Phase 11 built six hop lists per dev question in 1,366 s; six seeded lists plus the
    sentence ranking take about 25-40 min.
  - S5: Phase 11 took 7,051 s for 1,430 points, so 396 points take about 35 min.
  - S6: four systems × 5,000 questions plus about 20,000 sentences encoded online, about 2-3 h.
- **Memory.** The Phase 10 pass ran on the laptop within its 31.6 GB. The sentence cache is about
  46 MB (projection). The stages never run at the same time.
- **No new dependencies.**
