# Phase 1 tasks: Corpus, indexing units and dense baseline

> Spec: `1.spec.md` | Plan: `1.0_corpus_and_baseline.md`
> Atomic breakdown, since the phase has more than 10 implementation steps.

---

## T1: Config and package skeleton [Story: HU-1..HU-5]

- **Files**: `src/concept_embeddings_rag/config.py`, `src/concept_embeddings_rag/__init__.py`, subpackage `__init__.py` files, `tests/test_config.py`
- **Action**: create the `corpus/`, `embeddings/`, `retrieval/`, `evaluation/` subpackages and a config module holding paths, default seed, budgets (512/1024/2048/4096), model id and tokenizer id. Replace the scaffold `main()` placeholder.
- **Verification**:
  - [ ] Paths resolve relative to the project root, not the working directory
  - [ ] Budgets and seed are importable constants, not literals scattered through the code

## T2: Manifest and verified download [Story: HU-1] [depends on T1]

- **Files**: `corpus/manifest.py`, `corpus/download.py`, `tests/corpus/test_manifest.py`, `tests/corpus/test_download.py`
- **Action**: `CorpusManifest` dataclass with JSON round-trip and required-field validation; download with SHA-256 verification that skips the download when a valid file is already present.
- **Verification**:
  - [ ] A manifest missing a required field fails to load, loudly
  - [ ] A corrupted file (wrong hash) raises instead of being used
  - [ ] Second invocation over a valid file performs no download
  - [ ] The test uses a local synthetic fixture; the suite never touches the network

## T3: Deterministic subset and split [Story: HU-1] [depends on T2]

- **Files**: `corpus/split.py`, `tests/corpus/test_split.py`
- **Action**: select 2,000 questions with the manifest seed and split into 600 dev / 1,400 test using `sha1(qid)` rather than an RNG stream.
- **Verification**:
  - [ ] Two runs with the same seed produce identical selection and split
  - [ ] Split sizes are exactly 600 and 1,400, with no question in both
  - [ ] The split is unchanged when the surrounding code changes

## T4: Unit pool with stable IDs [Story: HU-2] [depends on T3]

- **Files**: `corpus/pool.py`, `tests/corpus/test_pool.py`
- **Action**: build the unified pool of `IndexingUnit` objects, IDs as `sha1(title + text)[:16]`, deduplicate, preserve sentence segmentation, count tokens per unit.
- **Verification**:
  - [ ] The same paragraph always yields the same ID
  - [ ] No unit is split, merged or truncated
  - [ ] Duplicates across questions collapse into one unit
  - [ ] The real pool size is reported (open risk in the plan)

## T5: Gold resolution [Story: HU-2] [depends on T4]

- **Files**: `corpus/pool.py`, `tests/corpus/test_gold_resolution.py`
- **Action**: map each question's supporting facts onto unit IDs, raising on any gold that fails to resolve.
- **Verification**:
  - [ ] Every question ends up with exactly 2 gold unit IDs
  - [ ] An unresolvable gold raises; it is never dropped silently
  - [ ] Gold units are present in the pool

## T6: Embedding backend [Story: HU-3] [depends on T1] [P]

- **Files**: `embeddings/backend.py`, `tests/embeddings/test_backend.py`
- **Action**: `EmbeddingBackend` protocol plus a sentence-transformers implementation pinned by model revision, with L2 normalization.
- **Verification**:
  - [ ] A fake backend satisfies the interface, so tests need no model download
  - [ ] Output shape is `[n, 384]` and rows are L2-normalized
  - [ ] Swapping the backend requires no change outside this module

## T7: Embedding cache [Story: HU-3] [depends on T6]

- **Files**: `embeddings/cache.py`, `tests/embeddings/test_cache.py`
- **Action**: persist to `.npz` plus a JSON sidecar, cache key from (model, revision, unit set hash, normalization), validate alignment on load.
- **Verification**:
  - [ ] A second run over an unchanged pool recomputes zero embeddings
  - [ ] Changing the model or the pool produces a new artifact instead of overwriting
  - [ ] A vectors/IDs length mismatch aborts the load
  - [ ] No `pickle` anywhere in the path

## T8: Dense retriever [Story: HU-4] [depends on T7]

- **Files**: `retrieval/base.py`, `retrieval/dense.py`, `tests/retrieval/test_dense.py`
- **Action**: `Retriever` interface and cosine-similarity retrieval over the full pool.
- **Verification**:
  - [ ] With handcrafted vectors, the ranking is the expected one
  - [ ] The same query returns the same ranking across runs
  - [ ] Retrieval never restricts itself to a question's own candidates

## T9: BM25 retriever [Story: HU-4] [depends on T4]

- **Files**: `retrieval/bm25.py`, `tests/retrieval/test_bm25.py`, `pyproject.toml`
- **Action**: BM25 behind the same interface, using `bm25s`. **Confirm the dependency before starting.**
- **Verification**:
  - [ ] Same interface as the dense retriever: the harness cannot tell them apart
  - [ ] A query with an exact term match ranks its unit first
  - [ ] Deterministic across runs

## T10: Budget filling [Story: HU-5] [depends on T4]

- **Files**: `evaluation/budget.py`, `tests/evaluation/test_budget.py`
- **Action**: greedy fill in rank order, skipping any unit that does not fit whole, never truncating; tokenizer declared in config.
- **Verification**:
  - [ ] A unit that does not fit is skipped and the next one is tried
  - [ ] The result never exceeds the budget
  - [ ] No unit is ever truncated
  - [ ] The same ranking and budget always yield the same context

## T11: Metrics [Story: HU-5] [depends on T5]

- **Files**: `evaluation/metrics.py`, `tests/evaluation/test_metrics.py`
- **Action**: Gold Paragraph Recall, Full Support Rate, Context Precision, Recall@K.
- **Verification**:
  - [ ] Both gold present -> recall 1.0 and full support 1
  - [ ] One of two -> recall 0.5 and full support 0
  - [ ] Precision counts gold among included units
  - [ ] Recall@K matches hand-computed values on a small fixture

## T12: Evaluation harness [Story: HU-5] [depends on T8, T9, T10, T11]

- **Files**: `evaluation/harness.py`, `tests/evaluation/test_harness.py`
- **Action**: loop over questions and budgets, measure latency, build `RunResult` with mandatory provenance, write append-only.
- **Verification**:
  - [ ] A `RunResult` with incomplete config is rejected
  - [ ] A new run never overwrites a previous result file
  - [ ] Dev and test are reported separately
  - [ ] The harness works with any retriever satisfying the interface

## T13: CLI [Story: HU-1..HU-5] [depends on T12]

- **Files**: `cli.py`, `pyproject.toml`, `tests/test_cli.py`
- **Action**: `fetch`, `build`, `embed`, `evaluate` subcommands; point the script entry point at the real CLI.
- **Verification**:
  - [ ] Each subcommand runs standalone and is idempotent
  - [ ] `evaluate` fails with a clear message if the previous stage has not run
  - [ ] Help text states what each stage produces and where

## T14: Real run and baseline numbers [Story: HU-5] [depends on T13]

- **Files**: `docs/plans/phase_1/1.results.md`
- **Action**: run the full pipeline over the 2,000-question subset, record dense and BM25 results with their provenance, and read them critically: an implausible baseline usually means a broken pipeline, not a discovery.
- **Verification**:
  - [ ] Every table cell carries the configuration that produced it
  - [ ] Recall@K is compared against published HotpotQA figures as a sanity check
  - [ ] Real pool size and embedding time recorded
  - [ ] Test-split numbers are produced once, at the end, and no decision is taken against them
