# Phase 13: choosing P1's bridge entity by the words around its mention — implementation plan

> Functional spec: [`13.spec.md`](13.spec.md), approved 2026-09-27 and frozen. This plan was
> **approved by the author on 2026-09-27**. It decides HOW; a change to any spec rule is a
> written deviation `13.Y_*.md`.
>
> Simplification rule: one question, **eight steps**, no `13.tasks.md`, reuse before
> generalization. Everything runs on the laptop; no money is spent. Code for a step past a stop
> state is not written: a stage that can never run breaks the simplification rule (the Phase 12
> precedent).

## Objective

> Does scoring each of P1's entities by the BGE similarity between the question and the words
> around its mention, and hopping only from the best-scored entities, retrieve the full
> multi-hop evidence more often than P10-C at FullWiki scale?

Primary endpoint: Full Support @2,048 on `test-11` (5,000 HotpotQA train `hard` questions), P13
against frozen P10-C, one two-sided exact McNemar test, α = 0.05. Preregistered secondary: P13
against P10-B, same test; it cannot change the label. Terminal states: `SCREEN_STOP`, `DEV_STOP`,
`BRIDGE_CHOICE_SUPPORTED`, `BRIDGE_CHOICE_NOT_SUPPORTED`, `BRIDGE_CHOICE_REGRESSION`.

## Author stop points

1. **`SCREEN_STOP` (S3)**, or a screen population different from 2,651.
2. **A D4 reproduction miss (S5)** or **`DEV_STOP` (S6)**.
3. **Before the held-out pass (S7).** It opens `test-11`. It runs once, after `fit.json` is
   committed, and only on explicit authorization.
4. Two attempts without progress.

## Implementation steps

- [ ] **S1 — Constants and the window rules (pure functions).**
  - Add the Phase 13 constants to `config.py`:
    - `PHASE_13_DIR` and the set names (reusing the Phase 11 names);
    - the window rule: `PHASE_13_WINDOW_WORDS = 5` and the rule id
      `"window-5w-sentence-clipped-masked-normalized-v1"`;
    - the seed grid `PHASE_13_SEEDS = (1, 2, 3, None)` (`None` = all), the grid step, the P10-C
      point (`None`, `0.5 / 0.3 / 0.2`);
    - the screen: population 2,651 and margin 5.0 points;
    - P10-C's dev count 4,801, the margin 33 and the bar 4,834;
    - the system names and the terminal states.
  - Add a new `evaluation/phase13.py`, pure functions over plain data:
    - `mentions(form, sentence)`: every match of the normalized form in the normalized
      sentence (the `phase12.occurs` pattern, with `finditer`), as `(first_word, last_word)`:
      the whitespace words the match overlaps;
    - `window(sentence, mention, width)`: up to `width` words before and after, clipped at the
      sentence edges, the mention's words left out, joined by one space; `""` when empty;
    - `entity_windows(p1_nodes, forms, sentences)`: node id → its non-empty windows, with
      sentence position and first word index, in sentence then word order;
    - `rank_entities(scores, weights)`: scored nodes by score descending, rarity weight
      descending, node id ascending (D1);
    - `seeds(ranking, p1_nodes, m)`: D2's seed set (`m = None` → every P1 node);
    - the screen rules: `first_mention(...)` (T1: sentence, match offset, node id), `rarest(...)`
      (T2: rarity weight, node id), `hit(choice, bridge)`, and `screen_verdict(...)`.
  - → `config.py`, `evaluation/phase13.py` (new).
  - Test: `tests/evaluation/test_phase13.py`:
    - word boundaries and regex metacharacters (via `occurs`' pattern), several mentions in one
      sentence, a mention that is the whole sentence (empty window);
    - clipping at both edges, masking of multi-word mentions, a match inside a word with an
      apostrophe (`"cameron's"`);
    - a Titanic-style fixture where the masked window ranks the director first;
    - ranking ties (rarity, then node id), `m` larger than the scored set, `m = None`;
    - T1 and T2 tie rules; the verdict at exactly +5.0 points and just below.

- [ ] **S2 — `cer p13-windows` (laptop CPU, dev only).**
  - Read the Phase 10 dev lists (digest checked against the Phase 10 `fit.json`), take the
    distinct first Dense units, read their sentence lists from the Phase 9 corpus
    (`_phase_9_corpus`), and their entity nodes and forms from the Phase 9 index
    (`_p11_entity_index`, `config.ENTITY_HOP_TYPES`).
  - Build every window with `phase13.entity_windows` and encode them with
    `SentenceTransformerBackend()` at the pinned model and revision, as passages (no prompt).
    Any other model is refused.
  - Write once `data/phase13/cache/windows/windows-dev-<key>.npz`: `unit_ids`, `node_ids`,
    `positions`, `first_words` (one row per window) and float32 L2-normalized `vectors`. The key
    hashes model, revision, window rule, set name and the sorted P1 unit ids. Its manifest
    records model, revision, resolved revision, units, windows, seconds, host, the vectors
    digest, the Phase 10 dev-lists and entity-index digests and the C2 coverage.
  - → `evaluation/phase13.py` (cache read/write, mirroring `phase12`'s), `cli.py`.
  - Test: the key changes with the set and the window rule; write-once; a manifest whose digest
    does not match its NPZ is refused on load.

- [ ] **S3 — `cer p13-screen` (laptop, dev only) — stop point 1.**
  - Inputs, all digest-checked: the Phase 10 dev lists, the Phase 9 dev questions (gold), the
    entity index, the S2 window cache, the Phase 9 dev question vectors (key
    `4894aceb0406c63a`, as `_p12_dev_question_vector` reads them), and for the descriptive rule
    the Phase 12 sentence cache (read-only).
  - Population: for each dev question, each gold paragraph outside the Dense top 10, in the index,
    sharing ≥ 1 entity node with P1; its bridge set. The count must equal 2,651, or the stage
    stops before computing any hit rate.
  - Per question: entity scores from the cached windows (max `sim`), the ranking, W, T1, T2; per
    item the three hits. Descriptive: the per-entity Phase 12 rule and W's first-2 and first-3
    bridge share.
  - Write `screen.json` once (counts, rates, reference, margin, verdict, descriptive figures,
    digests, commit) and **commit it**. On `SCREEN_STOP` the phase goes to S8's documentation
    half; S4-S7 are not written.
  - → `evaluation/phase13.py`, `cli.py`.
  - Test: on a small fixture, the population filter (inside the top 10, not in the index, no
    shared entity), the hit counts per rule, and the refusal when the population count differs.

- [ ] **S4 — The window-seeded hop stage (only after the screen passes).**
  - Add `gated_hop_columnwise(index, weights, columns, *, p1_nodes, seeds, read, depth)` next to
    `seeded_hop_columnwise` in `evaluation/second_hop.py`: scores over all of P1's arm nodes as
    `node_hop_columnwise` does, then keeps only rows holding at least one seed; exclusion,
    positivity, ties and the cut unchanged. The Phase 9 and Phase 11 functions are not touched.
  - Add `WindowSeededHopStage(index, weights, *, columns, m, forms, windows, question_vector)` to
    `retrieval/entity_hop.py`, shaped like `SentenceSeededHopStage`. `windows` is a small source
    with `windows_of(unit_id)`: `CachedWindows` reads the S2 cache and refuses an unknown unit;
    `OnlineWindows`, for the pass only, builds and encodes a unit's windows on first use, keeps
    them and times the work per question.
  - P13 reuses `QueryTripleFusedRetriever` (`retrieval/fusion.py`) with this stage.
  - → `evaluation/second_hop.py`, `retrieval/entity_hop.py`.
  - Test: `tests/retrieval/test_window_hop.py`:
    - at `m = None` the stage equals `ColumnwiseEntityHopStage` bit for bit on the existing
      random-index fixtures;
    - at `m = 1` only paragraphs holding the seed enter, and they are ordered by their full
      overlap with P1 (a fixture where Phase 12's rule would tie them);
    - no scored entity gives an empty list with `positives = 0`;
    - `OnlineWindows` encodes each unit once and times it.

- [ ] **S5 — `cer p13-lists` and the D4 reproduction (laptop) — stop point 2.**
  - Reuse the Phase 10 dev lists (Dense and BM25 are not re-run), the entity index, the S2 cache
    and the dev question vectors, and require the committed `screen.json` with a pass verdict.
  - For each dev question, the window-seeded hop list at each `m`, depth 100, with `positives`
    and the seeds.
  - Write `dev-lists.jsonl.gz` and its manifest (digest; the Phase 10 dev-lists, window-cache,
    entity-index and `screen.json` digests; seeds per question median and p90 per `m`;
    candidate-set sizes; commit, host, seconds).
  - D4: the `m = all` list equals Phase 10's `entity-hop` list for every dev question, and P13 at
    `m = all`, `0.5 / 0.3 / 0.2`, replayed through `measure_system`, gives 4,801 with 0 differing

    `phase12.reproduction_verdict`'s shape. A miss stops the phase.
  - → `evaluation/phase13.py`, `cli.py`.
  - Test: the reproduction verdict (pass, count miss, per-question miss, list miss); the stage
    refuses without a committed passing `screen.json`.

- [ ] **S6 — `cer p13-fit` (laptop, dev only) — stop point 2.**
  - The 4 `m` × 66 weight triples = 264 points, each re-fusing the cached dev lists, replayed

  - Write `fit.json` once (grid, curve, selection, tie rule, gate, 4,801, dev-lists digest,

  - → `evaluation/phase13.py`, `cli.py`.

- [ ] **S7 — `cer p13-eval --authorized-pass` (laptop) — stop point 3; written only if S6 goes.**

  - Loads the Phase 9 inputs, `test-11` (`phase11.load_test_11`), its Phase 11 question vectors

  - Measures P10-A, P10-B (0.5 / 0.5), P10-C (Phase 10 weights) and P13 (selected `m` and

  - → `evaluation/phase13.py`, `cli.py`.

- [ ] **S8 — `cer p13-outcome`, results, delivery.**

## Technical notes

- **Reuse.** Inputs: `_phase_9_inputs`, `_phase_9_corpus`, `_p11_entity_index`,
  `_p12_dev_question_vector`, the Phase 10 dev lists, `phase11.load_test_11`. Hop and fusion:
  `second_hop` arm columns and weights, `fuse_lists`, `QueryTripleFusedRetriever`,
  `ReplayRetriever`. Measurement: `supported`, `gold_recall_sum`, `measure_system`, `write_run`,
  `latency_summary`, `exact_two_sided_p`. Checks: `_p10_fit_is_committed`, the write-once helpers,
  `phase12.reproduction_verdict`'s shape, `phase12.weight_grid`. No Phase 9-12 function is
  modified.
- **Why the identity holds.** At `m = all` the seed set is every P1 arm node, so every row with a
  positive score holds a seed and the gate removes nothing: `gated_hop_columnwise` equals
  `node_hop_columnwise`. S4 tests it; D4 checks it on all 7,405 dev questions.
- **Where the words come from.** `IndexingUnit.sentences` of the Phase 9 corpus, normalized with
  `nodes.normalization.normalize`. Windows are cut from the normalized text, so the match offsets
  and the words live in the same string; the spec declares the normalized text as a limitation.
- **The screen population** reimplements, in tested code, the definition of the unversioned Phase
  12 closing diagnostic (`data/phase12/closing-diagnostic/diagnostic.py`): gold outside the Phase
  10 Dense top 10, present in the index, sharing an arm node with P1. The 2,651 check ties the two.
- **Question vectors.** Dev reads the Phase 9 vectors (rented GPU); `test-11` reads the Phase 11
  vectors (laptop CPU). Windows are encoded on the laptop CPU for both. Recorded as a limitation,
  as in Phase 12.
- **Latency.** `measure_system` times the whole `retrieve`; `OnlineWindows` times its own window
  building and encoding per question; the report subtracts and shows both, so D9 stays comparable
  with Phase 10. A P1 already seen in the pass reuses its windows, as a small cache would.
- **Time (projection, not measurement).**
  - S2: about 50,000-60,000 windows. Phase 12 encoded 22,444 sentences in 656.6 s, and windows
    are shorter: about 15-30 min, plus about 20 min to load the FullWiki corpus.
  - S3: a few minutes after loading the index, the lists and the caches.
  - S5: Phase 12 built six lists in 1,014.2 s; four lists take about 12-20 min.
  - S6: Phase 12 fitted 396 points in 1,461.7 s; 264 points take about 16 min, after the corpus
    load.
  - S7: four systems × 5,000 questions plus about 35,000-40,000 windows online, about 2-3 h.
- **Memory and disk.** The window cache is about 85 MB (projection). Stages never run at the same
  time; the Phase 10 pass fitted in the laptop's 31.6 GB.
- **No new dependencies.**
