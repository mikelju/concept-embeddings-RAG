# Phase 5 Results: Research Closure

Date: 2026-09-15

## 1. Scope of the result

This document closes the research line represented by the current concept-space implementation. It is not a claim about every possible implementation of the original hypothesis.

The tested operationalization was:

- HotpotQA distractor validation, with a unified pool of 19,366 paragraphs and 2,000 questions;
- dense retrieval with `BAAI/bge-small-en-v1.5` (384 dimensions);
- concept spaces induced by sparse non-negative coding of the pooled paragraph embeddings, with K = 512, 1,024, 2,048 and 4,096;
- conceptual retrieval and dense + conceptual score fusion (System B);
- diffusion over the paragraph × concept matrix with partial restart, seeded from dense or conceptual retrieval (System C);
- evaluation at a fixed context-token budget.

The values below are transcribed from the technical review supplied with this closure. They are not recomputed here.

## 2. Main test result

Full Support at a 2,048-token context budget, 1,400 test questions:

| System | Full Support |
|---|---:|
| Concepts alone | 0.355 |
| BM25 | 0.759 |
| Dense | 0.825 |
| System B: dense + concepts | 0.825 |
| System C: diffusion, dense seed | 0.821 |
| Control: dense + BM25 | **0.864** |

The fitted System B weight was 1.0 on dense, so the concept signal received no weight in the selected fusion. The dense + BM25 control is materially stronger than dense alone.

## 3. Phase 4 mechanical result

The diffusion system did not expand the candidate set. It returned the 100 seed paragraphs reordered rather than promoting previously unseen paragraphs.

The reported explanation is arithmetic: the propagation reaches a very broad portion of the 19,366-unit pool, while the seed distribution is too flat and the tested restart values (0.2–0.8) keep seed mass above new candidates. The review estimates the crossover threshold at approximately 0.10; the tested grid stayed above it.

This means the negative result of System C should not be interpreted as evidence that every possible graph or diffusion formulation cannot expand retrieval.

## 4. Second-hop diagnostic

On the bridge-failure diagnostic, a concept-based second hop was weaker than simpler alternatives:

| Second hop | Top-10 | Top-100 |
|---|---:|---:|
| Continue the dense list | 0.297 | 0.696 |
| BM25 with the question | 0.449 | 0.722 |
| Dense neighbours of p1 | 0.392 | 0.652 |
| BM25 with p1 text | **0.443** | **0.741** |
| Best tested concept variant (K=4,096, all concepts) | 0.108 | 0.430 |

Reducing the number of concepts per paragraph from the full representation to 1, 2 or 4 reduced recall further.

## 5. What the experiment rules out

Within the tested formulation and ranges, the evidence does not support further tuning as the default path for improvement:

- K = 512–4,096 did not make conceptual retrieval competitive with dense;
- reducing concepts per paragraph did not help;
- the tested query operators did not create useful complementarity;
- score-level fusion selected dense alone;
- diffusion with the tested restart and normalization grid did not introduce new candidates;
- rarity damping did not change the overall verdict.

## 6. What remains untested

The following remain genuinely open and should not be described as disproven:

- concepts explicitly extracted from paragraph text (LLM, NER, or term extraction);
- a corpus whose structure matches the original homogeneous-domain hypothesis;
- thematic / satellite questions rather than mainly entity-bridge questions;
- token-level sparse representations;
- entity graphs with personalized propagation;
- sharper seeds, restart below the tested range, reserved expansion capacity, or intersection-style operators;
- stronger dense retrieval and reranking;
- response-level metrics and direct evaluation of satellite information.

## 7. Scientific verdict

### Supported negative conclusion

> On the tested HotpotQA setup, a concept space produced by sparse dictionary learning over pooled dense paragraph embeddings did not provide measurable complementary retrieval value over the dense baseline, either by direct conceptual retrieval, score fusion, or the tested diffusion-based expansion. A dense + BM25 control was clearly stronger.

### Explicit non-conclusion

This does **not** refute the broader hypothesis that a corpus can be represented through interpretable concepts discovered from text and that retrieval can expand through those concepts. The tested implementation changed the meaning of "concept" relative to the original proposal: concepts became dictionary atoms derived from dense paragraph embeddings rather than concepts extracted from the text itself.

The benchmark also differs from the original proposed setting: HotpotQA is heterogeneous and its difficult bridge links are frequently carried by named entities, while the original proposal emphasized thematic multi-concept and satellite-context retrieval.

## 8. Decision for the next block

The current Phase 4 formulation is closed as a negative result. Do not spend the next block tuning its existing parameters by default.

The highest-information next experiment is a cheap pilot using text-derived entities/concepts on a small set of bridge failures, with the existing dense/BM25 setup held fixed. The pilot should first answer one question: can explicit text-derived nodes recover missing gold paragraphs through the already-retrieved context where the pooled-embedding concept space could not?
