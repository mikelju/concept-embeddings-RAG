# Deviation 5.1: the extraction cost ceiling rises from 25 to 35 USD

## Context

Step 12 of [`5.0_text_derived_concepts.md`](5.0_text_derived_concepts.md), task T12: the real
sample. `uv run cer extract --sample` extracted the 20 paragraphs with the lowest unit ids,
synchronously, with the exact request the full run uses, and stopped at the checkpoint D4 declares.
The full run had not been started, and no batch had been submitted.

## Problem

The estimate measured on the sample is **33.17 USD**, above the **25 USD** ceiling that the spec
(HU-2, Restrictions) and the plan (D2, D4) fixed. `cer extract` refuses to start above the ceiling,
so the phase cannot reach T13 without a decision.

### Measured on the sample

Recorded in [`data/extraction/sample-report.json`](../../../data/extraction/sample-report.json),
model `claude-sonnet-5`, prompt digest `0107de3ae9b4e4a3`:

| Figure | Value |
|---|---|
| Sample paragraphs within schema and bounds | **20 of 20** |
| Mean input tokens per request (API `usage`) | **779.4** |
| Mean output tokens per request (API `usage`) | **124.7** |
| Cost of the sample, standard rates | **0.056116 USD** |
| Sample paragraph length, project tokenizer | mean 132.45, median 141.5, min 36, max 280 |
| Corpus paragraph length, project tokenizer | mean 124.42, median 112.0, min 15, max 1,850 |
| Pool size | 19,366 |
| Paragraphs still uncached | **19,346** |

### The estimate, exactly as `estimate_full_cost` computes it (D4)

```
n        = 19,346                       paragraphs not yet cached
in_tok   = 779.4                        sample mean input tokens per request
out_tok  = 124.7                        sample mean output tokens per request
margin   = 1.5                          EXTRACTION_ESTIMATE_MARGIN, output only
rate_in  = 2.00 USD / million tokens    EXTRACTION_INPUT_USD_PER_MTOK
rate_out = 10.00 USD / million tokens   EXTRACTION_OUTPUT_USD_PER_MTOK
batch    = 0.5                          BATCH_PRICE_FACTOR

estimate = ( n * in_tok / 1e6 * rate_in
           + n * out_tok * margin / 1e6 * rate_out ) * batch

         = ( 19,346 * 779.4 / 1e6 * 2.00          = 30.1565448
           + 19,346 * 124.7 * 1.5 / 1e6 * 10.00 ) = 36.1866930
           * 0.5
         = 33.1716189 USD
```

At batch rates the input part is 15.08 USD and the output part, with the margin, 18.09 USD. Without
the margin the same arithmetic gives **27.14 USD**, which is also above 25.

## Root cause

The plan's rough figure of about 19 USD assumed some 475 input tokens per request. The API measures
779.4: the frozen instructions and the structured-output schema cost about 650 tokens per request on
top of the paragraph itself, and D2 pays them once per paragraph. The measurement did what D4 put it
there to do. The assumption was wrong; the protocol was not.

The sample slightly **over**-represents paragraph length: its mean is 6.5% above the corpus's, and
its median 26% above. The estimate therefore leans high rather than low, and the margin stays as
declared.

## Adopted solution

Decided by the author at the checkpoint, **option 1**:

- **The ceiling rises from 25 to 35 USD.** 35 USD covers the estimate with its margin (33.17 USD)
  and leaves the expected cost without margin (27.14 USD) well inside it.
- **Everything else stays as specified and planned.** The extractor stays Sonnet 5, one paragraph
  per request (D2), the prompt, the schema, the bounds, the 1.5 output margin, batches of 5,000, the
  single resubmission, the 1% failure finding, and the gate.
- **The 20 sample paragraphs are not extracted again.** They are cached under the full run's keys
  (model, prompt digest, unit id), which the full run reads before building any request. It submits
  only the 19,346 uncached paragraphs, so the sample is neither re-requested nor billed a second
  time. This was checked against the cache on disk: the 20 cached unit ids are exactly the sample's.
- **The sample report is versioned**, so the figures this decision rests on stay in the history
  beside it. It records the 25 USD ceiling it was taken under; it is kept as written rather than
  regenerated.
- **The full extraction waits for the author's explicit approval** of the spend, as D4 and D14
  already require.

Rejected at the same checkpoint: moving to Haiku 4.5 under the old ceiling, which would undo the
extractor choice made in the specification conversation, and grouping several paragraphs per request,
which would undo D2's isolation.

## Impact

- `src/concept_embeddings_rag/config.py`: `EXTRACTION_COST_CEILING_USD` from 25.0 to 35.0, and
  `tests/test_config.py` with it. No other constant changes.
- `5.spec.md`: the ceiling in HU-2 and in Restrictions, with a reference to this document.
- `5.0_text_derived_concepts.md` and `5.tasks.md`: the ceiling in the success criteria, D2 and T1.
- `.gitignore` and `.secrets.baseline`: the sample report is versioned, and the unit ids and prompt
  digest it holds are added to the baseline as audited false positives. The D12 path exclusion is not
  widened.
- No code path, test, artifact or decision beyond the ceiling is touched.
