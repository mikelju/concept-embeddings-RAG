# Spec Phase 4: Query-aware iterative expansion (System C)

> Functional specification - WHAT to build and WHY.
> The HOW belongs in the phase plan (`4.0_phase_name.md`).
> Acceptance criteria are verified with `/7-verificar` at the end of the phase.

---

## Problem and objective

**Problem**: three phases in, this project has a concept space that is well-formed, interpretable,
and - used one hop at a time - worth nothing in retrieval. Phase 3's System B fitted its fusion
weight at `w = 1.0` and is dense to four decimals at every budget on both splits; its 2x2 against
dense is perfectly diagonal, and it recovers **0** of the 72 dev questions that defeat both
baselines. The dense+BM25 control, built by the same code and fitted by the same procedure, gains
**+3.9 points of Full Support** on test. The headroom a hybrid can take was real and available; the
concept space, scored once, did not reach it.

None of that tested the hypothesis. Phase 1 isolated the failure mode this project exists for - the
retriever finds the entity the question names and never reaches the bridge entity it does not name -
and **no one-hop retriever has a mechanism for a second hop, whatever space it scores in**. Phase 3
ended by pointing here with two facts: conceptual-only retrieval answers 5 dev questions dense does
not, **4 of them among those 72**, and every one of the five is a conjunction of two topics - a
Florida place *and* baseball, an Irish biography *and* combat sports. A dense query is one point and
must land near one paragraph; a concept vector can ask for the paragraph that is about both subjects
at once, which is the shape of a bridge. The signal exists, it is sparse, and score-level fusion
provably cannot reach it: at any weight loud enough to contribute those 4, the concept space loses
more questions than it gains.

**Objective**: stop following the question and start navigating the corpus. Build **System C** -
expansion by diffusion over `X`, with partial restart on the question at every round - measure it in
the unchanged harness at equal token budget, and find out whether the second paragraph can be reached
through concepts at all. The phase ends with a number for System C against four rivals on both
splits, a per-query trace saying which concept brought which paragraph in, and the configuration
frozen before test was read.

**The bar, stated before anything is measured.** The honest rival is no longer dense. It is the
**dense+BM25 control at 0.8643 Full Support on test at 2,048 tokens**, because that is what a cheap
lexical hybrid already achieves on this corpus without any of this machinery. System C beating dense
(0.8250) and not the control is a result, and it is to be reported as exactly that rather than as a
win.

**What closes this phase.** A reproducible number for System C at four budgets on both splits,
against dense, BM25, System B and the control, with its cost. **A negative verdict closes the phase
as well as a positive one.** What would not close it is a win nobody can attribute - which is why the
seed arms of HU-3 exist, and why the restart parity of HU-2 is a test rather than a claim.

**What this phase cannot prove.** The §69 verdict belongs to Phase 5, which compares all four systems
and runs the ablations; this phase delivers System C and its measurements, not the report. And
HotpotQA's hops are laid out by an annotator, so any gain here is a gain on **Type B** questions.
Type C - satellite context the corpus would have to produce without annotation - stays the declared
gap of the master plan and Phase 6 material.

## User stories

### HU-1: The corpus is navigated by diffusion over `X`, not by a second ranking

**As** the researcher,
**I want** the expansion to be a propagation unit -> concept -> unit through `X` and `X`ᵀ,
**so that** what moves the retrieval is the co-activation structure Phase 2 built, and so that the
mechanism is deterministic, cheap and inspectable rather than a model's guess.

**Acceptance criteria:**
- [x] Propagation is computed as **sparse matrix-vector products** against `X` and `X`ᵀ. The
      unit x unit matrix (19,366²) is **never materialized**, at any iteration, in any intermediate
- [x] The operator is written down in the phase plan and recorded in every result config: which
      matrix, which view, which normalization, applied in which order
- [x] **Operator normalization is measured, not assumed.** An un-normalized operator concentrates
      mass on the best-connected units of the corpus; whether that matters on this space is a
      measured cell of the grid, not a belief held in a comment
- [x] The ranking is deterministic including ties, broken by unit id exactly as every other retriever
      in this project does. The same question and the same artifacts produce the same list every run
- [x] A test asserts one diffusion step against a reference computation on a small hand-built matrix,
      so the implementation is checked against arithmetic rather than only against itself
- [x] The retriever reads no concept label, no gold annotation and no split. The guard tests that
      keep `retrieval/` free of the labels artifact keep passing unchanged

### HU-2: The restart makes the expansion query-aware, and that is checkable

**As** the researcher,
**I want** a declared fraction of the mass returned to the question's own signal at every round,
**so that** §52 holds by construction - the association depends on the query and not on the corpus's
global co-occurrence - and so that the contribution of expansion can be read against a system that
did not expand.

**Acceptance criteria:**
- [x] The restart is applied at **every** iteration, not only at the first, and its fraction is a
      recorded parameter of the run
- [x] **At `restart = 1.0` the system reproduces its seed system's ranking exactly**, to floating
      point tolerance, and a test asserts it. This is the property that makes every later difference
      attributable to expansion rather than to a changed pipeline
- [x] At `restart = 0.0` the walk is query-independent by construction. It is measured once on dev
      and reported as the declared failure mode of §52-§53, so that "expansion cannot drift toward
      global co-occurrence" rests on a number instead of on design intent
- [x] The question's signal that is restarted onto is the same one the seed used, and a result cannot
      record one while having restarted onto the other

### HU-3: Two seeds, so that a gain can be attributed

**As** the researcher,
**I want** the diffusion measured from a dense seed and from a purely conceptual seed, with identical
machinery,
**so that** "System C wins" can be separated from "the dense retriever already brought almost
everything", which is the exact ambiguity that made HU-5 necessary in Phase 3.

The source document describes both: §50 retrieves chunks from `X`, §51 starts from the chunks already
retrieved. Phase 3 supplied the fact that decides how to treat them: conceptual-only retrieval loses
284 of 600 dev questions but answers 5 that dense does not. A purely conceptual seed starts from a
ranking known to be far worse; a dense seed starts from the strongest one available and risks
measuring dense with extra steps.

**Acceptance criteria:**
- [x] Two seed arms, both declared before measurement: **dense-seeded** (System C proper) and
      **conceptual-seeded** (the isolating variant). Both are measured on dev and both on test
- [x] The dense seed is System A's retriever object, unchanged. The conceptual seed is Phase 3's
      conceptual retriever at the **inherited frozen configuration**: K = 512, dictionary
      `d84c327aa8af0cdc`, view `raw`, damping `idf`, query operator `projection_full`
- [x] Both arms run the **same diffusion code with the same parameters**. A difference between them
      is a difference of seed and of nothing else, and a test asserts the two retrievers differ only
      in the seed they were constructed with
- [x] The inherited configuration is **read from the frozen Phase 3 selection artifact and verified**,
      never retyped into this phase's code. The phase refuses to run if that artifact's digest does
      not verify, or if it names a dictionary other than the one being loaded

### HU-4: The expansion stops on its own, by a criterion declared in advance

**As** the researcher,
**I want** a stopping rule on newly contributed mass, with a hard cap and a recorded iteration count,
**so that** §54 is implemented rather than approximated by a constant number of rounds, and so that
the cost of the system is visible per question instead of averaged away.

**Acceptance criteria:**
- [x] The stop is **per-query**, on new mass falling below a declared threshold, with a hard
      iteration cap and the harness's token budget as the outer limit
- [x] The threshold is **declared in `config.py` and not fitted**. It is not a third degree of
      freedom, and a phase that ends up needing to fit it records that as a deviation
- [x] The iterations actually run are recorded **per question** and reported as a distribution, not
      as a mean alone: a system that stops at round 1 on 90% of questions is a different system from
      one that runs to the cap, and a mean of 1.4 hides both
- [x] Hitting the cap is recorded and reported per run. A run where most questions hit the cap is a
      finding about the threshold and is written down as one

### HU-5: Every expansion leaves a trace that can be read

**As** the researcher,
**I want** a per-query record of which concept entered at which iteration and which unit it brought,
**so that** a recovered question can be explained rather than celebrated, and so that the conjunction
hypothesis of HU-8 has evidence instead of an anecdote.

**Acceptance criteria:**
- [x] The trace is produced **by the retriever as it runs**, not reconstructed afterwards from the
      final ranking - a reconstruction can disagree with the run it claims to explain
- [x] Producing the trace **changes no score**. A test asserts the ranking is identical with tracing
      on and off
- [x] It is written as a **versioned artifact for a declared sample** of dev questions - at minimum
      the cells this phase cares about: the 72 that defeat both baselines, plus whatever System C
      recovers or loses against dense. The sampling rule is declared before the run, not chosen after
      seeing which questions turned out interesting
- [x] Concept **labels may be attached when the trace is read for the report, never when it is
      produced**. The trace artifact holds concept ids; `retrieval/` still cannot import the labels

### HU-6: The configuration chosen on dev, frozen, and test read once

**As** the researcher,
**I want** exactly two free parameters, fitted on dev under a declared cap and frozen in a versioned
artifact,
**so that** a dev win is not an artifact of how many configurations were tried, and so that this
phase inherits Phase 3's discipline rather than re-inventing a weaker one.

**Acceptance criteria:**
- [x] **Exactly two free parameters**: the restart fraction and the operator normalization. Both
      grids are written into `config.py` before any measurement. Everything else is fixed by
      declaration (stop threshold, iteration cap, `top_k = 100`) or inherited frozen from Phase 3
- [x] A **declared cap on dev evaluations for the whole phase (40)**, counted and reported. Exceeding
      it requires a deviation document (`4.Y`), not a quiet second sweep
- [x] Selection is on **Full Support at the 2,048-token budget on dev**, both seed arms reported
      separately, with the full table at all four budgets alongside so a ranking that holds at only
      one budget is visible as such. Gold recall is reported beside it everywhere, so the comparison
      with Phases 1-3 stays direct
- [x] When the margin between two cells is **below what 600 questions can resolve**
      (`resolvable_margin`, the Phase 3 function, unchanged), the tie is broken by **cost: fewer mean
      iterations wins**. The rule is declared here, before the numbers, and §73 is its reason
- [x] The chosen configuration is **frozen into a versioned artifact before the test split is read**,
      carrying `evaluated_on = "dev"`, a digest verified on load, and the digest of the Phase 3
      selection it inherits from
- [x] A test asserts the **test split cannot be reached from the selection path**, as Phase 3's does
- [x] Phase 3's four inherited decisions - K, view, damping, query operator - are **not re-opened**.
      Evidence that one of them is wrong for diffusion is a recorded deviation (`4.Y`), never a
      silent re-choice

### HU-7: Measured in the unchanged harness against four rivals, cost included

**As** the researcher,
**I want** System C measured by the same code, at the same budgets, against dense, BM25, System B and
the control,
**so that** the numbers join the same table as everything else, and so that a gain paid for in
latency or tokens is reported with its price as §73 demands.

**Acceptance criteria:**
- [x] System C is measured through `evaluate_retriever` **unmodified**, at the four budgets, on both
      splits, at `top_k = 100`. If the harness has to change to accommodate it, that is a finding
      about the interface and is recorded as a deviation
- [x] Its rivals' numbers are **read from the Phase 3 result files, not recomputed**, and the pool
      hash, split, tokenizer, seed and `top_k` of those files are checked to match this phase's run
      before any comparison table is produced
- [x] **Cost is reported per system**: mean latency, mean units included, and for System C the
      iteration distribution and the mean number of sparse products per query
- [x] Every result config carries the full diffusion configuration, the seed arm, the inherited
      Phase 3 decisions and the digests of both selection artifacts

### HU-8: The conjunction hypothesis tested rather than repeated

**As** the researcher,
**I want** the 2x2 regenerated for System C and the recovered questions read through their concepts,
**so that** Phase 3's named hypothesis - the questions the concept space uniquely answers are
conjunctions of two topics - is confronted with 600 questions instead of being quoted again.

**Acceptance criteria:**
- [x] The cross-tabulation is regenerated with `failure_analysis.py` **unchanged**: System C against
      dense, and System C against the control
- [x] **How many of the 72 System C recovers is a first-class number, with the qids named.** The
      comparison is already calibrated: System B recovers 0, the control recovers 6
- [x] The recovered questions are read through their top concepts and their Phase 2 labels, exactly
      as Phase 3 read its five, against the **pre-registered** question: are they conjunctions of two
      topics?
- [x] **This analysis selects nothing.** It is read after the freeze, like Phase 3's damping table,
      and no parameter moves because of it
- [x] **If System C recovers nothing, that is written with the same prominence a recovery would
      get**, and the trace of HU-5 is used to say where the expansion went instead

## Data contracts

### `DiffusionRetriever` (runtime object, its configuration recorded in every result)

| Field | Type | Meaning |
|---|---|---|
| name | str | The system name that reaches the result filename (`expansion`, and the isolating arm's own) |
| matrix | `ConceptMatrix` | The inherited `X`: K = 512, view `raw`, hash-verified on load |
| dictionary | `ConceptDictionary` | `d84c327aa8af0cdc`, the atoms the question enters through |
| seed_retriever | `Retriever` | Dense (System C) or conceptual (the isolating variant) |
| seed_arm | str | `dense` or `conceptual`; a result cannot record one and have run the other |
| restart | float | Fraction of mass returned to the question's signal each round |
| normalization | str | How the propagation operator is normalized; one of the declared arms |
| stop_threshold | float | New mass below which expansion stops. Declared, not fitted |
| max_iterations | int | Hard cap |
| concept_weights | array \| None | The inherited `idf` damping, applied as Phase 3 applies it |
| inherits | dict | The Phase 3 selection digest and the four decisions it froze |

**Invariants:**
- The unit x unit matrix is never materialized, at any iteration.
- `restart = 1.0` reproduces the seed retriever's ranking exactly.
- A unit whose row of `X` is all zeros gains no mass by diffusion, ever. Phase 2 measured zero orphan
  units at every K, so this is an assertion that should hold rather than a limitation introduced.
- The retriever reads no label, no gold annotation and no split label.

### `ExpansionTrace` (JSON artifact, one file per declared sample)

| Field | Type | Meaning |
|---|---|---|
| qid | str | The question, by its benchmark id |
| seed_arm | str | Which of the two arms produced this trace |
| config_digest | str | The configuration that ran, so a trace can never be read against another run |
| iterations | list | One entry per round: concepts entering with their mass, units entering with their mass, new mass contributed, and whether this round stopped |
| stop_reason | str | `threshold`, `cap`, or `converged` |

**Invariants:**
- The trace describes the run that produced the ranking, identified by the same config digest.
- It holds concept **ids**, never labels.
- Producing it changes no score.

### `ExpansionSelection` (JSON, one per phase, versioned)

Same shape and the same rules as Phase 3's `SelectionReport`, which is the pattern rather than a
coincidence: measured cells, the chosen cell, the runner-up and its margin, whether that margin was
resolvable, the tie-break applied, the decision ledger in the order the decisions were fixed,
`frozen_at`, `evaluated_on`, `seed`, `code_version`, `digest`.

| Added field | Type | Meaning |
|---|---|---|
| inherits_selection_digest | str | The digest of the frozen Phase 3 selection, checked against the artifact on disk |
| dev_evaluations_spent | int | Counted against the declared cap of 40, so the budget is auditable |
| stop_threshold / max_iterations | float / int | The declared constants, recorded so a later run can prove it used them |

**Invariants:**
- Every number in it is computed on dev or on the corpus. **No field is ever derived from test.**
- `frozen_at` precedes the `created_at` of every test-split result of this phase.
- Written atomically, never overwritten, and verified on load in this order: `evaluated_on`, then the
  digest, then the pool, then the dictionary keys and the inherited Phase 3 digest it names.

### `RunResult.config`, extended

Beyond the Phase 1 required keys and the Phase 3 conceptual ones: `seed_arm`, `restart`,
`normalization`, `stop_threshold`, `max_iterations`, `mean_iterations`, `iterations_histogram`, the
four inherited Phase 3 decisions, and the digests of both selection artifacts.

## Restrictions

- **Platform**: Windows on ARM64, CPU only. Nothing here re-embeds the corpus, re-induces a
  dictionary or re-codes `X`; all three are read from cache, hash-verified. No new dependency is
  expected - `scipy.sparse` is what diffusion needs - and any that turns out to be needed goes
  through the ASK FIRST rule before it is added.
- **Memory**: `X` is 19,366 x 512 and sparse. The concept x concept matrix is 512 x 512 and harmless;
  the unit x unit matrix is 375 million entries and is the thing this phase must never build. Every
  propagation is two sparse products.
- **Phase 1, 2 and 3 artifacts are frozen inputs.** The pool, the embedding caches (corpus and
  questions), the dictionaries, the matrices, the diagnostics, the labels, the Phase 3 selection and
  the Phase 3 result files are read, never rewritten and never invalidated.
- **Determinism**: every stochastic step takes an explicit seed and the seed travels in the config.
  Diffusion as specified is deterministic; if any part of it turns out not to be, that is a defect,
  not a tolerance.
- **Artifact integrity**: verify on load, do not merely record - the rule the Phase 1 audit
  established. `.npz` and JSON only; no `pickle`, no `joblib`, no `allow_pickle=True`.
- **Secrets**: unchanged. `ANTHROPIC_API_KEY` is read from `.env` by the labelling stage only, and
  never printed, logged or written into an artifact.
- **ASCII in `print()`, logging and Python strings.** Markdown may use Unicode.

## Anti-goals (what this phase does NOT do)

- **NO LLM inside the expansion loop.** The master plan lists an LLM-in-the-loop variant as optional;
  this phase declares it **out of scope** and defers the decision to Phase 5. The reason is the
  founding decision it would violate: with a model in the loop there is no telling whether the
  concept space worked or the model guessed well, and the deterministic method has to be measured
  first to be the thing the variant is compared against.
- **NO re-opening of the Phase 3 decisions.** K, the view of `X`, the damping and the query operator
  are inherited frozen. Re-choosing them here would spend the dev split on a decision already made
  and make the two phases incomparable.
- **NO pruning of concepts.** Still a declared Phase 5 ablation. This phase damps by the inherited
  rarity weight and removes nothing.
- **NO re-induction, no new K, no change to the embedding model or the indexing unit.** All three
  invalidate caches that cost hours and make every recorded metric incomparable.
- **NO tuning against test, in any form.** Not a threshold, not a restart fraction, not a
  normalization, not a quick look to check nothing is broken. Test is read once, on a frozen
  configuration.
- **NO explicit graph construction.** The graph stays implicit in `X`, as §12 and §58 frame it.
  Materializing nodes and edges is Phase 6 material and conditional on Phase 5.
- **NO hierarchy signal.** §56's fourth signal is Phase 6, and the benchmark cannot exercise it:
  Wikipedia offers only article -> paragraph -> sentence.
- **NO answer generation and no answer-quality metrics.** No faithfulness, no completeness, no LLM
  judge. The primary metric stays supporting-fact recall within the budget.
- **NO second benchmark.** MuSiQue cross-validation is Phase 5.
- **NO ablation catalogue and no comparative report.** The variants of this phase are the ones
  written above; the systematic ablations and the §69 verdict are Phase 5's work.
- **NO comparison at fixed K instead of fixed budget.** System C retrieves more units by design,
  which is exactly why the founding decision measures at equal tokens sent.
- **NO change to the harness, the budget rule or the metrics.** This phase adds config keys to a
  result, not code to `evaluation/harness.py`.

## Existing code context

  `ConceptualRetriever`: the conceptual seed arm, and the code that already turns a question into a
  damped concept vector. The restart vector of HU-2 comes from here.
- `src/concept_embeddings_rag/retrieval/dense.py` - the dense seed arm, unchanged.
- `src/concept_embeddings_rag/retrieval/fusion.py` - not used by System C, but the source of this
  project's conventions on combining rankings and on declaring what was combined.
- `src/concept_embeddings_rag/concepts/coding.py` - `load_matrix`, the views, and `WEIGHT_SEMANTICS`,
  which is the authority on what a weight of `X` means and therefore on what diffusing over it may
  assume.
- `src/concept_embeddings_rag/evaluation/selection.py` - `SelectionReport`, `save_selection`,
  `load_selection`, `resolvable_margin`, `Decision` and the freeze ordering check. The Phase 4
  artifact follows this file rather than inventing a second pattern, and reads the Phase 3 selection
  through it.

  every system.

  evaluation budget belong here.
- `src/concept_embeddings_rag/cli.py` - the staged pipeline. This phase adds an expansion-selection
  stage and extends `evaluate`, each refusing to run when its input is missing and naming the stage

- `docs/plans/phase_3/3.results.md` - the rivals' numbers, the 2x2 this phase is compared against,
  and the five questions whose shape HU-8 tests.
- `docs/plans/phase_2/2.results.md` - the selected space, its hub at 7.2% of the pool, and the
  co-activation structure the diffusion moves through.
- `docs/refs/descripcion-proyecto.md` §8, §50-§54 - the hypothesis this phase implements, in the
  author's own words.
