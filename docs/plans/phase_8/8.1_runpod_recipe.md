# Deviation 8.1 — RunPod operating recipe

> Operational runbook for the **measurement-host part of deviation 8.1 only**.
> Read this end to end before opening the pod. The CPU-side code, corpus selection,
> reproduction Level 1 and local preflights must already be committed and pushed.

This run does **not** reopen Phase 8 and does **not** touch the 1,400 held-out questions.
It measures the same frozen 600 dev questions over the nested C19/C100/C250/C500
retrieval corpora.

## 6. Free preflight on the pod

Run these before any `scale-run` measurement:

```bash
uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
df -h .
uv run cer scale-run --model bge --preflight-only
uv run cer scale-run --model qwen --preflight-only
```

`torch.cuda.is_available()` must be `True`.

The real `scale-run` performs a second, measurement-host-specific preflight
**before model load**. It checks:

- CUDA is available;
- sufficient free disk remains;
- reconciliation has no `data_stop`;
- the frozen C500 selection and token artifacts load;
- the historical corpus and question caches required by D-L1 exist;
- D-L1 reproduces that model's historical C19 count exactly.

If D-L1 does not reproduce exactly, the command stops with
`reproduction_stop`. Do not load a model, delete a cache or widen a tolerance.

## 7. Measure BGE

Run exactly once:

```bash
uv run cer scale-run --model bge --hourly-rate-usd <RATE>
```

The intended sequence is:

```text
measurement-host preflight
  -> D-L1 from historical caches
  -> pinned revision / resolved snapshot / safetensors SHA-256
  -> one C500 paragraph encode
  -> one 600-question dev encode
  -> C19 Level 2 from the C500 prefix
  -> if Level 2 passes: C100, C250, C500
```

There is no independent embedding job per scale. C19/C100/C250/C500 are aligned
prefixes of the one C500 vector block.

Expected new files include:

```text
data/phase8_1/embedding-bge.json
data/phase8_1/scale-bge.json
data/phase8_1/run-dense-bge-c19-dev-*.json
data/phase8_1/run-dense-bge-c100-dev-*.json
data/phase8_1/run-dense-bge-c250-dev-*.json
data/phase8_1/run-dense-bge-c500-dev-*.json
data/phase8_1/cache/...
data/phase8_1/cache/questions/...
```

Each scale reading records both `run_file` and `run_digest`.

### BGE STOP conditions

Inspect the command output and `scale-bge.json`.

- `difference == 0`: Level 2 confirms Level 1.
- `abs(difference) == 1`: continue, but preserve the recorded caveat. D-L1 is
  used to narrow the source; otherwise it remains residual
  numerical/host/re-encoding variation.
- `abs(difference) >= 2`: `reproduction_stop`. **STOP.** Do not run Qwen and do
  not interpret scale figures.
- If the C500 retrieval probe reports that mean seconds/query exceeds the frozen
  ceiling, preserve all artifacts and **STOP before another scale run**. The
  declared blockwise exact fallback is then implemented in code; the threshold
  is not changed.

Do not overwrite `scale-bge.json` or `embedding-bge.json`.

## 10. Classify on the laptop, not on the pod

Only after both model artifacts have been downloaded and neither run recorded a
stop:

```powershell
uv run cer scale-outcome
```

`scale-outcome` refuses to classify unless:

- both models have exactly C19/C100/C250/C500;
- both have exactly 600 questions;
- both carry the same frozen `question_set_hash`;
- neither carries `data_stop` nor `reproduction_stop`.

The classifier applies the already-frozen outcome order. Do not change a
threshold after seeing the measurements.
