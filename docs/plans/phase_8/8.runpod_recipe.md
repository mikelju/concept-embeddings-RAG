# Phase 8 — RunPod operating recipe

> Operational runbook for the one rented-GPU pass Phase 8 needs. Every command below was read off
> the code at commit **`ff84f0d0b7c3`** (`phase-8-strong-dense`) — the CLI syntax, the artifact
> names and the file paths are the real ones, not the plan's shorthand.
>
> **This recipe executes measurements. Read it end to end before opening a pod**: the meter runs
> while you read the manual.

Plan: [`8.0_strong_dense.md`](8.0_strong_dense.md) · Spec: [`8.spec.md`](8.spec.md)

---

## The shape of the run, and why it is not one pass

```text
POD      strong-embed                 corpus + dev questions       ~80 MB of vectors
  |                                   (test questions NOT touched)
  v
LAPTOP   strong-dense                 dev fit + three systems      -> the stop rule verdict
  |
  +-- verdict STOP  -> the phase closes on its dev figures. Destroy the pod. Nothing else runs.
  |
  +-- verdict PASS  -> upload dev.json back to the pod
          |
POD      strong-embed --test          1,400 held-out questions
          |
LAPTOP   strong-dense --test          the single held-out measurement
```

The gate sits **between two GPU passes on purpose**. `strong-embed --test` refuses to run without a
digest-valid `dev.json` whose verdict is `pass`, so a failed premise leaves the held-out split
neither encoded nor measured. Keep the pod alive across the gate and the second pass is minutes of
work on 1,400 strings; let it die and you pay for a second rental and a second model download.

**Only `strong-embed` needs the GPU.** Both `strong-dense` paths read cached vectors and load no
model, so they run on the ARM64 laptop.

---

## Two costs, and they are never added together

| Figure | Where it lives | What it means |
|---|---|---|
| `embedding_usd` | `data/phase8/embedding.json`, written by the run | `hourly_rate_usd * embedding_seconds / 3600` — the charge **attributable to the encoding pass**, an upper bound on it |
| `question_usd` | `data/phase8/embedding-test.json` | the same arithmetic for the held-out encoding |
| **Session total** | RunPod Billing, after the fact | The **whole rental**: image pull, model download, the uploads, idle time between the two passes. Goes in `8.results.md` beside the attributable figures, **in the currency RunPod invoiced**, never converted |

Phase 7's precedent is the shape to copy: 0.03 + 0.05 USD attributable against a **0.34 EUR** session
invoice, reported as three separate numbers with the discrepancy explained. Learning the session
total later **never requires rewriting `embedding.json`** — that is why the two are not one field.

## 2. Create the pod, and copy the rate

- **GPU**: 1x RTX 4090 (24 GB) — the Phase 7 machine, and what the projections will be read against.
- **Template**: a CUDA 12.x PyTorch image on Ubuntu 24.04.
- **Disk**: 40 GB is comfortable. The Qwen3-0.6B weights are ~1.2 GB; `uv sync` pulls a CUDA torch.

**Before you click deploy, copy the hourly rate RunPod shows for the exact GPU you are renting** —
the contracted USD/hour, not a list price from elsewhere. That number is the `--hourly-rate-usd`
argument, and it is what turns seconds into `embedding_usd` and into the 5M projection. Phase 7
contracted at 0.74 USD/h; yours will differ. Write it down now:

```text
RATE = ____________   USD/hour, as shown in RunPod at deploy time
```

Passing nothing defaults to `0.0`, which silently makes every cost figure and the whole 5M
projection zero. That is a valid setting for owned hardware and a falsified record on a rented one.

## 4. Install, upload the pool, preflight

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv sync
```

`uv sync` alone. `pyproject.toml` resolves `torch` from the `pytorch-cu126` index on
`linux x86_64`, so CUDA comes from the lock rather than from a manual install. The `phase7` group is
**not** needed: GLiNER never runs on the pod — its index is read on the laptop.

**Upload the pool.** `data/pool.json` (15 MB) is not tracked by git; `data/manifest.json` is, and
arrives with the clone. From the laptop:

```bash
scp -P <POD_SSH_PORT> data/pool.json root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/pool.json
```

(The exact host and port come from the RunPod UI; `runpodctl send` / `receive` is the alternative if
you prefer not to open SSH.)

Preflight, all of it free:

```bash
uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
uv run python -c "import json; d=json.load(open('data/manifest.json')); print(d)"
ls -la data/pool.json
uv run cer strong-embed --help
```

`torch.cuda.is_available()` must print `True`. If it prints `False` the pass will silently run on CPU
and record `device: cpu` — correct provenance, ruinous throughput.

## 5. The first pass: corpus and dev only

```bash
uv run cer strong-embed --hourly-rate-usd <RATE>
```

This encodes **19,366 paragraphs and the 600 dev questions, and nothing else**. The held-out
questions are not read, not encoded, not touched.

What it prints, in order, and what each line proves:

```text
[OK]   model provenance verified: Qwen/Qwen3-Embedding-0.6B at <resolved revision>,
       model.safetensors sha256 <first 16 hex>...
[INFO] encoding 19366 paragraphs and 600 dev questions
[INFO] 19366 paragraphs in <N> min (<X> paragraphs/s), 1024 dimensions, max_seq_length <M>
[INFO] projection to 5000000 paragraphs: <H> h, <U> USD (linear from measured throughput);
       this pass costs <C> USD
[OK]   embedding artifact written -> data/phase8/embedding.json
```

The provenance line comes **before the model load** by construction: pin format, resolved revision
and weight digest are checked first, and a mismatch aborts before a single vector exists.

Three things that abort the stage rather than producing a wrong number, so you do not need to watch
for them: a resolved revision different from the pin, a vector block whose width is not 1024, and a
query prompt that is not byte-identical to the declared one.

If the stage dies after encoding, **do not simply re-run it**: it refuses an existing cache, by
design, because it would otherwise record a wall clock for work it did not do. Read the refusal, and
delete the named cache file deliberately if you really do want to re-encode.

## 6. What to keep, and what to download

The pod's `data/cache/` was empty before this pass, so everything in it is Phase 8's. Download all
of it plus the artifact:

```bash
# from the laptop
scp -P <POD_SSH_PORT> -r root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/cache        data/
scp -P <POD_SSH_PORT>    root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/phase8/embedding.json  data/phase8/
```

That is, by name:

| File | What it is |
|---|---|
| `data/phase8/embedding.json` | the provenance + cost artifact; `dev.json` will anchor on its digest |
| `data/cache/embeddings-<corpus_cache_key>.npz` + `.json` | 19,366 x 1024 corpus vectors and their sidecar |
| `data/cache/questions/embeddings-<question_cache_key>.npz` + `.json` | the 600 dev question vectors and their sidecar |

Both keys are recorded in `embedding.json` under `corpus_cache_key` and `question_cache_key` — read
them from there rather than guessing from filenames:

```bash
uv run python -c "import json;d=json.load(open('data/phase8/embedding.json'));print(d['corpus_cache_key'],d['question_cache_key'])"
```

**Do not delete anything on the pod.** The second pass needs `embedding.json` and the model cache
still in place.

**Leave the pod running** while the gate is evaluated. If you must stop it, stop rather than
terminate, so the volume survives.

## 7. The gate, on the laptop

```bash
uv run cer strong-dense
```

It loads the Phase 7 GLiNER index from `data/phase7/gliner/`, verifies it against its pinned digest,
fits both hybrids on dev and measures the three systems. No model is loaded.

The line that decides the phase is the last `[INFO]` before the `[OK]`:

```text
[INFO] stop rule: <count>/600 supported, 488 required to continue, verdict PASS
```

- **`verdict PASS`** — `count >= 488`. Strong Dense beat the inherited 487/600 by at least one
  question. Continue to step 8.
- **`verdict STOP`** — `count <= 487`. The premise failed: this model is not stronger on this corpus.
  **Stop here.** Report the dev result, destroy the pod, and write `8.results.md` on the dev figures.
  Do **not** try another encoder inside Phase 8 — choosing a model after seeing dev is the
  leaderboard the master plan forbids, and it would destroy the meaning of any held-out figure that
  followed.

The three dev system figures print above that line. Reading them is legitimate — dev is the split
choices are made on. The held-out split is what stays closed.

## 8. If and only if PASS: the gated held-out encoding

Send the gate's verdict back to the pod first — `strong-embed --test` reads `dev.json`, checks its
digest and refuses on anything but `pass`:

```bash
# from the laptop
scp -P <POD_SSH_PORT> data/phase8/dev.json root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/phase8/dev.json
```

Then, on the pod, with the **same rate**:

```bash
uv run cer strong-embed --test --hourly-rate-usd <RATE>
```

```text
[INFO] encoding 1400 held-out questions
[OK]   held-out encoding written -> data/phase8/embedding-test.json
```

`embedding-test.json` records both parent digests (`embedding_digest`, `dev_digest`), so the artifact
itself carries the proof that the gate authorized the encoding.

Download:

```bash
scp -P <POD_SSH_PORT> -r root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/cache/questions  data/cache/
scp -P <POD_SSH_PORT>    root@<POD_HOST>:/workspace/concept-embeddings-RAG/data/phase8/embedding-test.json  data/phase8/
```

| File | What it is |
|---|---|
| `data/phase8/embedding-test.json` | the gated encoding's provenance and its own cost |
| `data/cache/questions/embeddings-<test key>.npz` + `.json` | the 1,400 held-out question vectors |

## 10. The number to copy from Billing

When the pod is stopped, open **RunPod → Billing** and copy the **session total actually charged**,
with its currency, exactly as invoiced:

```text
SESSION TOTAL = ____________   (currency as charged, no conversion, no invented exchange rate)
```

in `8.results.md`. Do **not** reconcile them by editing either artifact, and do **not** substitute
the invoice for the 5M projection.

## 11. Checklist before destroying the pod

Run this on the **laptop** — it checks that what you downloaded is complete and self-consistent.
The laptop is Windows, so run it in **Git Bash**: the heredoc is not PowerShell syntax.

```bash
uv run python - <<'PY'
import json, pathlib
d = pathlib.Path("data/phase8")
emb = json.loads((d / "embedding.json").read_text(encoding="utf-8"))
keys = [emb["corpus_cache_key"], emb["question_cache_key"]]
test = d / "embedding-test.json"
if test.exists():
    keys.append(json.loads(test.read_text(encoding="utf-8"))["question_cache_key"])
for key in keys:
    for base in (pathlib.Path("data/cache"), pathlib.Path("data/cache/questions")):
        if (base / f"embeddings-{key}.npz").exists():
            print("[OK] ", base / f"embeddings-{key}.npz")
            print("[OK] ", base / f"embeddings-{key}.json")
            break
    else:
        print("[MISSING]", key)
print("[INFO] dim", emb["dim"], "max_seq_length", emb["max_seq_length"])
print("[INFO] resolved_revision", emb["resolved_revision"])
print("[INFO] weights_sha256", emb["weights_sha256"][:16], "...")
print("[INFO] embedding_usd", emb["embedding_usd"], "at", emb["hourly_rate_usd"], "USD/h")
PY
```

Then, before you terminate:

- [ ] `embedding.json` downloaded, and `dim = 1024`, `resolved_revision` equal to the pin
- [ ] corpus `.npz` **and** `.json` sidecar downloaded
- [ ] dev question `.npz` **and** `.json` sidecar downloaded
- [ ] `uv run cer strong-dense` ran on the laptop from those caches without re-encoding anything
- [ ] the stop-rule verdict recorded, whichever it was
- [ ] if PASS: `embedding-test.json` and the held-out question cache downloaded, and
      `uv run cer strong-dense --test` already run
- [ ] `hourly_rate_usd` in the artifacts equals the rate RunPod actually charged
- [ ] **session total copied from Billing** — it is unavailable once you stop looking for it
- [ ] nothing under `data/phase7/`, `data/token_counts.json` or any pre-Phase-8 cache was modified
      on the laptop (`git status` on the laptop is the check)

Only then terminate the pod.

## Known caveat to carry into `8.results.md`

Phase 7 recorded it and it will recur: the `hardware` block reports the RunPod **host**, not the
container. Expect `cpu_count`, `torch_threads` and `ram_bytes` far larger than what the pod was
actually allocated. It does not affect a GPU throughput figure — the RTX 4090 is recorded correctly —
but the CPU fields must not be read as the machine that did the work. Declare it rather than clean
it up.
